# Dを条件付きで利用する設計の根拠

既存の32始点の結果を再集計した図。RWやキャッシュ実験を追加実行したものではない。全6グラフ、alpha=0.01と0.1について同じ図を保存した。PNGは閲覧用、PDFは資料用。図中の説明は英語。

## 主張と図の対応

1. **01_node_conditions**：nodeについて、H/O/Rの大小別に「D大の再アクセス率−D小の再アクセス率」を示す。右側ほどD大が有利。Hが大きい場面、Oが小さい場面などでDの利用価値を検討できる。各パネルの横軸スケールは異なるため点の位置だけでパネル間の大小を比べない。
2. **02_horizon_sensitivity**：候補条件H大・O小・R大を、それぞれ独立に、再アクセス期限10/100/1000アクセスで比較する。同一の対象イベント・大小閾値を使っている。期限が長くなるとDが有利になるかを確認する図であり、保持期限1000がキャッシュの最適値であることを示すものではない。
3. **03_node_edge**：同じ条件でnodeとedgeを比較する。nodeの傾向をそのままedgeに適用できないことを示す。nodeのDは次数、edgeのDは両端ノードの平均次数である。
4. **04_stratum_comparison**：同じ始点の差をさらに差し引き、H大−H小、O小−O大、R大−R小でDの効果が変わるかを直接検討する。正の値は候補側の条件でDの関連がより強いことを表す。ただし、両条件とも負でもこの差は正になりうるため、必ず01と一緒に読む。

## 図を用いた結論の書き方

「次数Dと将来の再アクセス率の関連は、対象がnodeかedgeか、評価する再アクセス期限、アクセス時点のH/O/Rの条件、およびグラフによって異なる。したがってDを一律に高く評価するのではなく、これらの条件に応じて利用する適応的な設計を検討する。」

具体例としてalpha=0.01、期限1000のnodeでは、H大でBA +6.80ポイント、Amazon +3.01ポイント、Enron +3.48ポイント、Slashdot +1.70ポイント。一方VLDBではH大でも負であり、全グラフに共通する規則とはしない。SlashdotはH小の−4.57ポイントからH大の+1.70ポイントに符号が変わるため、条件を分ける必要性を説明する例になる。

O小は相対的な区分であり、初回アクセスやコールドスタートと同義ではない。HはRW内の歩数でありBFS距離ではない。Rは前回アクセスからの近さ。H大・O小・R大を同時に満たす場合の効果は、この二要素分析では検証していない。

## 集計方法と限界

各始点の各条件でD大・D小それぞれ20イベント以上ある場合の差を計算し、始点を等重みで平均。01〜03の95%区間は元のconditional_effects.csvの始点bootstrap区間。04は両条件に共通する始点をペアにし、5000回、seed=20260928のpercentile bootstrapで算出。04の数値はstratum_contrasts.csvに保存。

大小は始点・対象型・要素ペアごとのイベント数をなるべく二分する閾値で、同じ値を分割しない。再アクセス期限は同一始点の複数RWを連結したアクセス列上の間隔。実時間のTTLや同一サーバ上のキャッシュ保持期間とは異なる。

これらは同じデータで見つけた条件の探索的可視化であり、多重比較補正をしていない。区間は始点間のばらつきを表し、異なるグラフや独立した実験全体への一般化を保証しない。因果効果、キャッシュヒット率向上、通信削減は未検証。学習による条件選択の有用性は、別の始点・seedを評価用に分けたキャッシュ実験で確認する必要がある。
