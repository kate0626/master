# 研究の流れの整理 と RTT 不均一モデルの課題

> 目的: ①「前提 → 問題 → 実測 → 最終地点の RTT 不均一モデル」までの論理の流れを構造化する。②不均一化モデルをどう工夫すべきか／そもそも何が課題なのかを明確にする。

---

## Part 1. 最終地点 (RTT 不均一モデル) までの流れ

### 1.0 一行で言うと

> **分散グラフ上のランダムウォークでは全 hop が越境＝毎回認可 (RTT コスト) が発生する。これをキャッシュで削減したい。ただし容量無制限 (Memo) はメモリを食って拡張性がない。容量 100 程度に有界化したうえで、削減「時間」を最大化するキャッシュ IN/OUT を設計する。RTT が不均一になると「ヒット数最大化」では不十分で「節約 RTT 最大化」へと目的が変わる ── ここが最終地点。**

### 1.1 前提 (システムモデル)

- グラフは bipartite 展開: `node ⇄ edge_entity(edge_u_v) ⇄ node`。
- **ノードとエッジは別サーバ・別認可主体**。
  - `server0` = ノード認可、`server1` = エッジ認可。**両方とも start 依存** (同じエッジでも start により allow/deny が変わる)。
  - ⇒ キャッシュキーは `(start, entity)` が正当。キャッシュは **per-start** (認可が start 依存なので start 間共有不可)。
- 1 論理ステップ = bipartite hop 2 回 = **認可 2 回**。全 hop が越境するので、**サーバ移動 (=越境 RTT) が時間コストの本体**。
- 実行設定: 1 start から walker を **100 本 並行**実行 (`--walks`)。複数 start は評価の平均化のため。

### 1.2 キャッシュを導入すべき基準 (コスト比較)

```
キャッシュ導入コスト  <  RTT を払う処理コスト   ⇒ キャッシュする価値あり
```

- **RTT が小さい**: サーバ間時間が気にならない → キャッシュ不要 (導入コストの方が高い)。
- **RTT が大きい**: 無視できない時間になる → 削減が必要。
  - **均一の場合**: どの認可も同じ RTT。`総時間 = 認可回数 × RTT` なので「**ヒット率最大化 = 時間最小化**」。← これまでの実測はすべてこの世界。
  - **不均一の場合**: 認可ごとに RTT が違う。「ヒット率最大化」では時間最小化にならない。**距離 (RTT) を考慮したモデルが必要**。← **最終地点 / Part 2 のテーマ**。

### 1.3 問題: 容量無制限は拡張性がない

- Memo (容量制限なし) は walk 長に比例してキャッシュが膨張 → メモリ圧迫。
- RW は本来複数視点からアクセスされ、「元データの 10% 程度に収める」というキャッシュの定石を大きく超える。
- **理想容量 ≈ 100**。容量を有界化したまま時間削減を達成したい。

### 1.4 問題の数値構造: 47% one-hit / 53% multi-hit

| 項目 | 値 |
|---|---|
| 総 lookup | 15,701 |
| miss (初回アクセス=別個キー数) | 7,424 (47.3%) |
| hit | 8,277 (52.7%) |
| 1 キーあたり平均 lookup | 2.11 回 |

- **47% は 1 回しか使われない** = 保存されるだけで容量を食い、ヒットに貢献ゼロ (one-hit-wonder)。
- 最大ヒット率 = 53% (multi-hit ぶんだけ)。
- ⇒ **本丸は退去 (OUT) ではなく admission (IN)**。47% を最初から入れなければ、ヒット率を 1pt も落とさず容量がほぼ半減する。

### 1.5 なぜ LRU が失敗するか

- LRU は **退去しか触らず、47% を一旦全部入れる**。
- 容量を削ると、入れた 47% が押し出し合い、**53% の有用エントリまで巻き添えで消える** → ヒット率崩壊。
- これが「**容量を削減すると時間が増える**」の正体。

### 1.6 実測で分かった核心 (uniform RTT 世界での結論)

> 「構造プライア (距離・次数) で予測する」路線は実測で否定され、「実測した再利用 (頻度) を守る」路線に確定した。

1. **one-hit-wonder はほぼ全部エッジ**:
   - ノード: one-hit 23–26% / multi 74–77%、無制限上限ヒット率 0.82–0.84 (優良資産)。
   - エッジ: one-hit 61–63% / multi 37–39%、上限 0.44–0.48。しかもエッジは数が圧倒的 (amazon 2.4M vs node 392k)。

2. **距離・次数は再利用予測に無情報**: degree AUC 0.53–0.54、BFS 距離 AUC 0.55–0.57 (≈0.5)。
   → **構造プライアでは multi/one を分離できない**。

3. **再利用は超ローカル & walk 内再訪**: 「最初の数本の walker で再利用予測」仮説は反証 (AUC≈0.5)。再利用はアンサンブル (別 walker 共訪) でなく**同一 walker の walk 内再訪**。reuse 距離中央値 = ノード 0 / エッジ 3。

4. **OPT (Belady) ≈ Memo** (容量 100, 両グラフで再現):
   | | Memo | LRU | OPT | 余地(OPT−LRU) | Memo−OPT |
   |---|---|---|---|---|---|
   | ノード | 71.4 | 67.3 | 71.4 | **4.1pt** | 0 |
   | エッジ | 40.8 | 32.1 | 39.6 | **7.5pt** | 1.2 |
   | 合算 | 55.0 | 48.4 | 54.3 | **5.9pt** | 0.7 |
   - **Memo−LRU の差 (約 6.6pt) のほぼ全部が「容量不足」でなく「LRU の退去が下手」**。容量 100 でも賢い IN/OUT でほぼ Memo まで取り戻せる。
   - 余地の正体 = **one-hit-wonder 汚染**。recency だけ見る LRU が直近の 1 回きりキーを保持して再利用キーを押し出す。

5. **正攻法 = 頻度/scan 耐性 (LFU/ARC/TinyLFU 系 or 頻度保護つき独自)** で OPT 近似。
   - **エッジが主戦場** (余地 7.5pt・量も多い)。ノードとエッジで余地も機構も違う → **非対称 policy・非対称容量配分**。

### 1.7 提案手法の現在地 (uniform RTT 前提)

- **退去スコア (加法版)**: `V(e) = max(0, freq(e) − δ) + θ·w_prior(e)`、`H(e) = L + V(e)/size(e)`、argmin 退去・`L ← H_evicted`。
  - `w_prior(e) = (1−α)^hops × deg(e)` (PPR 局所近似、距離は walker の `hops_done` から取得)。
  - δ = 初回割引 (「2 回目で本物」)、θ = prior 強度。
- IN = 暗黙 admission (全 demand を初回認可で入れ、低 prior は即退去 → SLRU 的に protected/probation が創発)。
- 評価軸: 同一容量 N での auth_calls 比較 + 「目標ヒット率を保つ最小容量 (LRU 比で何分の 1)」。

> **ここまでが「均一 RTT」の世界。時間 ∝ 認可回数なので、ヒット率 (auth_calls) を目的関数にしてきた。**

## Part 2. RTT 不均一モデル ── 課題は何か、どう工夫するか

### 2.0 目的 = 「時間」を出す (この研究の操作的ゴール)

> **元々の出力**: RTT 未考慮の時間 (基準: 計算だけの時間)。
> **出したいもの**: RTT を考慮した実時間。

**時間の式 (これが目的関数の正体)**:
```
全体の時間 = RTT未考慮の時間(基準) + Σ(サーバ間移動) RTT
```

**「サーバ間移動」の正体 = キャッシュ MISS**:
- 認可要求がキャッシュで返れば移動なし。ミスなら越境して RTT を払う。
- ∴ **移動回数 = 総認可数 − ヒット数**。**ヒットは移動を 1 回消す = RTT を 1 回節約**。
- 「移動回数 (=ヒット数で決まる) によって、未考慮の時間との差が広がる」= **キャッシュが効くほど RTT 項が縮む**、という意味。

```
時間(キャッシュなし) = 基準 + (総認可数)        × RTT
時間(キャッシュあり) = 基準 + (総認可数 − ヒット数) × RTT
節約できた時間        = ヒット数 × RTT          ← ×1。×2 にしない (下記)
```

**注意: ヒット数に ×2 しない (RTT は定義上すでに往復)**:
- RTT = Round Trip Time = 「サーバへ要求 → 応答が返る」の **往復**そのもの。1 ヒットが消すのはこの 1 往復 = **1 × RTT**。×2 すると往復を二重計上する。
- 紛らわしい「2」は別の層の話: **1 論理ステップ = 認可 2 回 (node 認可 + edge 認可)** は本物だが、これは「認可単位で数える」式に既に入っている (総認可数がステップ数の約 2 倍)。「認可 1 回 = 往復 2 回」ではない。
- ×2 が正しくなるのは **単位を RTT でなく片道遅延 L で測るとき**だけ (`1 認可 = 2L`, `RTT = 2L`)。RTT という語を使う限り ×1 に統一する。

**均一 / 不均一でこの式がどう変わるか**:
| | 節約時間 | 目的関数 | 含意 |
|---|---|---|---|
| 均一 RTT | `ヒット数 × RTT(定数)` | **ヒット数最大化** = 時間最小化 | Part 1 はヒット率だけ見ればよかった |
| 不均一 RTT | `Σ_{各ヒット} RTT(そのヒット)` | **Σ RTT_saved 最大化** | 高 RTT に当てるヒットほど時間を多く節約 → ヒット数最大化では足りない |

> ⇒ 評価の出力は **「ヒット率」ではなく「時間 (秒)」**。`基準時間 + Σ_{miss} RTT` を policy ごとに出し、`Σ_{hit} RTT_saved` の大小で比較する。これが §2.1 以降の議論の土台。

### 2.1 まず「そもそも課題はあるのか」への答え: **ある。ただし条件つき。**

不均一モデルが意味を持つかどうかは、**RTT がエントリ間で違うか**で決まる:

- **RTT が完全に均一** → 距離は本当に無関係。「ヒット率最大化」で終わり。不均一モデルは不要。
- **RTT が不均一** → **目的関数が変わる**。これが本質的な課題:

```
均一:   最小化 Σ(miss)              = 最大化 ヒット数              … 全 hit が等価
不均一: 最小化 Σ_{miss} RTT(miss)   = 最大化 Σ_{hit} RTT_saved(hit) … hit ごとに価値が違う
```

> **キャッシュの価値は「ヒット数」でなく「節約した RTT の総和」になる。** 高 RTT のエントリは、たとえ再利用が少なくても 1 ヒットの価値が大きい。

### 2.2 核心の気づき: 距離は「予測子」としては死んだが「重み」として復活する

これが Part 1 と Part 2 をつなぐ最重要ポイント:

- **Part 1 の結論**: グラフ距離・次数は **再利用を予測しない** (AUC≈0.5)。「近いノードほど multi-hit」は成り立たない。
- **Part 2 の主張**: しかし **RTT 距離は予測子ではなく、確定した再利用の価値を測る重み**。役割がまったく違う扉から距離が戻ってくる。

```
価値(e) = (再利用回数: 実測 freq で測る) × (1 ヒットあたり節約 RTT: 距離で測る)
          └─ Part 1 の頻度保護 ─┘     └─ Part 2 の新しい軸 ─┘
```

→ 距離を「どのノードがヒットするか」の予測に使うと外れる (Part 1)。距離を「ヒットしたとき何秒節約できるか」の重みに使うのが正しい (Part 2)。

### 2.3 工夫の枠組み: Greedy-Dual の cost 項がついに効く

提案の退去スコアは GDSF (Greedy-Dual-Size-Frequency) 系。**Greedy-Dual には元々 cost (fetch コスト) 項がある**が、均一 RTT では cost が定数なので退化して LFU-size と区別がつかなかった。**不均一 RTT は、この cost 項を活性化させる場面**:

```
均一:   H(e) = L + freq(e) / size(e)                     (cost = 定数 → 消える)
不均一: H(e) = L + freq(e) · RTT_saved(e) / size(e)       (cost = RTT が効く)
```

提案の加法版に組み込むなら:

```
V(e) = [ max(0, freq(e) − δ) + θ·w_prior(e) ] · RTT_saved(e)
H(e) = L + V(e) / size(e)
```

- `RTT_saved(e)` = そのエントリがヒットしたとき回避できる越境 RTT。
- **uniform は RTT_saved ≡ 1 の特殊ケース**として連続的に包含できる (ablation で「RTT 項あり/なし」を比較すれば、不均一化の効果がそのまま測れる)。

### 2.4 RTT 不均一の源泉 = **グラフのパーティショニング** (α でも walk でもない)

> **核心 (2026-06 修正)**: RTT が不均一になるか・どう不均一になるかは、**エンティティをどのサーバに割り当てるか = パーティショニング**で決まる。α は walk の長さ/拡散を変えるが RTT 構造そのものは生まない。**同じ walk でも分割方式を変えれば RTT 列がまるごと変わり、キャッシュすべきノード (freq×RTT 上位) も変わる。**

エンティティ→サーバの割当には 2 つのレジームがあり、**RTT の構造がまったく違う**:

| レジーム | サーバ構成 | RTT の構造 | グラフ距離との関係 |
|---|---|---|---|
| **(i) 種別分割 (現状)** | server0 = 全ノード認可 / server1 = 全エッジ認可 (2 台) | RTT は **node 認可 / edge 認可の 2 値**のみ | **距離は RTT に効かない**。どのステップも node↔edge サーバ間を必ず跨ぐので、距離に関係なく RTT は 2 値。⇒ **model (c) は成立せず**、不均一は「**node vs edge の RTT 非対称**」に縮約 (= Part 1 の node/edge 非対称配分と直結) |
| **(ii) 局所性分割 (Louvain many-server)** | コミュニティ → サーバ (多数台) | RTT は **どのコミュニティ/サーバか**で連続的に変わる | **距離 ≈ サーバ距離 ≈ RTT** が成立 ⇒ **model (c) `RTT=f(d)` が有効** |

**含意 (重要)**:
- **「距離 = RTT」(model c) が意味を持つのは (ii) 局所性分割のときだけ。** 現状の (i) 種別 2 分割では距離は RTT に無関係で、不均一は node/edge の 2 値差に縮む。
- データに `dataset/Louvain/graph/*.gr` がある = **(ii) を構成する材料は既にある**。Louvain コミュニティ → サーバ割当にすれば「グラフ距離が大きい=別コミュニティ=遠いサーバ=高 RTT」が**分割方式から導かれる構造的事実**になる。
- ∴ 研究設計の最初の分岐は **「どの分割を前提に RTT を論じるか」**。(i) なら node/edge 非対称の話 (§2.6 前半)、(ii) なら距離関数の話 (§2.6 後半・§2.7)。**両方を比較する**のが自然な構成 (分割方式そのものを変数にできる)。

**(ii) を採るときの `f(d)` の定義** (model c の具体化):
- 1 walk ステップは隣接移動 = 距離 1 なので「現在地→次エンティティ」は退化。採るのは **`d = dist(start, e)` (始点からの BFS 最短距離)**。
- small-world ゆえ `d ∈ [0, ~14–17]`。`f` は単調増加 (`f(d)=1+βd` 線形 / `f(d)=RTT_min·c^d` 指数 / 実測表)。**β を不均一強度**としてスイープ → 均一 (β=0) ↔ 強不均一を連続化。
- より忠実には `f` を **「コミュニティ境界を何回跨ぐか」**で定義してもよい (Louvain 分割上の start→e のサーバホップ数)。これは純グラフ距離より分割構造を直接反映する。

### 2.5 【モデル c 専用の罠】`dist(start,e)` は「死んだ予測子」そのもの ── 役割を厳密に分離せよ

モデル (c) は `d = dist(start, e)` を使う。**これは Part 1 で AUC≈0.5 と否定された、あの距離変数そのもの**。だからこそ、二役の混同を機械的に防ぐ規律が要る:

| 使い方 | 問い | 答え | 可否 |
|---|---|---|---|
| **予測子 (旧路線・禁止)** | 「`d` が大きい → e は再利用される?」 | NO (AUC≈0.5) | ❌ 復活させない |
| **重み (新路線・採用)** | 「`d` が大きい → e の認可は RTT を多く食う?」 | YES (モデル c の定義そのもの) | ✅ これだけ |

**形式化での担保**:
```
V(e) = [ max(0, freq(e) − δ) + θ·w_struct(e) ] · f(d)
        └─ 予測は freq が全部やる ─┘            └ 重みのみ ┘
```
- `f(d)` は **掛け算の重みとしてのみ**入る。**admission の条件や予測には一切使わない**。
- 帰結チェック: 遠い (高 `f(d)`) が **再利用されない**エントリ → freq が上がらず `V` は低いまま → ちゃんと退去される (旧「遠い=入れない/近い=入れる」とは逆に、距離だけでは生き残れない)。
- 遠い **かつ** 再利用されるエントリ → 各ヒットの節約 RTT が大きいので厚く保護。これが (c) の唯一の効き筋。
- ※ `θ·w_struct` の PPR prior `(1−α)^hops·deg` と `f(d)` を**二重に距離で効かせない**よう注意 (prior は walk-hop 基準・admission 寄り、`f(d)` は構造距離・コスト重み。混ぜると距離が予測子に逆戻り)。迷うなら `f(d)` だけ残し prior を切る ablation を基準にする。

### 2.6 不均一化が既存結論をどう書き換えるか (分割レジームごと)

Part 1 の「**エッジは容量 100 では 1 枠の価値もない、100 枠は全部ノードへ**」は **均一 RTT 前提**。これがどう崩れるかは分割レジームで違う:

**(i) 種別分割の場合 — node/edge の RTT 非対称**:
- RTT は「node 認可 RTT」対「edge 認可 RTT」の 2 値。価値 = `freq × RTT_type`。
- もし **edge 認可サーバが遠い (高 RTT)** なら、one-hit 多く再利用の薄いエッジでも 1 ヒットの節約 RTT が大きく、「1 枠の価値なし」が**覆りうる**。
- ⇒ **node/edge 容量配分が RTT 比 `r = RTT_edge/RTT_node` で連続的に動く**。「どの `r` でノード優先→エッジ優先へ転じるか」が論点。

**(ii) 局所性分割の場合 — 距離駆動**:
- 価値 = `freq × f(d)`。**遠い (高 `f(d)`) かつ再利用されるエントリ**が近傍の高 freq を逆転する閾値が存在。
- node/edge で再利用構造と距離分布が違う (ノード=近傍ハブ集中・reuse 距離 0 / エッジ=分散・reuse 距離 3) ため、`f(d)` 重みは **node/edge に非対称**に効く。
- ⇒ **配分が不均一強度 β で連続的に動く**。「どの β でノード優先→エッジ優先へ転じるか」の閾値曲線。

> **研究価値の核心**: 均一では決着していた node/edge 配分が、(i) では RTT 比 `r`、(ii) では傾き β という 1 パラメータで連続的に動く。**両レジームで閾値曲線を描けば「分割方式が配分をどう変えるか」がそのまま貢献になる。**

### 2.7 RW の 2 つの軌道パターン と「頻度 × RTT」の同時考慮 (モデルの核心)

> **核心の主張**: 価値 = `freq(e) × f(d_e)`。最適キャッシュ集合は **頻度と距離の同時分布**で決まり、その同時分布は **RW の軌道パターン**で変わる。∴ RTT だけ・頻度だけでは決められない ── **両者を同時に見る必要がある**。
>
> ※ この節は **(ii) 局所性分割** (距離が RTT に効く) を前提とする。(i) 種別分割では距離は RTT に無関係なので、軌道パターンは freq だけを変え、freq×RTT の話は §2.6(i) の node/edge 非対称に縮む。**「軌道パターンが効くのも分割方式次第」** ── §2.4 の延長。

RW の軌道には 2 つのパターンがあり、どちらも実在する。**何がパターンを決めるかが本質**: walk の長さ (α) よりも、**分割境界が walk の経路に対してどう置かれているか** (= パーティショニング) の影響が大きい。同じ walk でも分割を変えれば「どこで遠サーバを踏むか」が変わる:

- **パターン A: 近傍から徐々に広がる** ── 近いコミュニティ内を繰り返し踏みつつ緩やかに外の (遠い) コミュニティへ拡散。
  - 距離×頻度の同時分布 → **近距離=高頻度、遠距離=低頻度** (頻度と距離が**負相関**)。
- **パターン B: 一度遠くへ行って近くへ戻る** ── 遠いコミュニティへ遠征し、その領域をある程度踏んでから近傍へ戻る。
  - 距離×頻度の同時分布 → **遠方ノードも中程度の頻度を獲得** (頻度の山が遠方にも立つ)。
  - ※ B が起きやすいかは **分割の粒度・境界の置き方**に強く依存する (細かい分割や、walk がよく通る経路を跨ぐ境界だと遠征が増える)。

**なぜキャッシュすべきノードが変わるか** (`freq × f(d)` で評価):

| ノードの位置 | パターン A (徐々拡散) | パターン B (遠征→帰還) |
|---|---|---|
| 近距離 | 高 freq × 低 RTT → 値 **中** | 高 freq × 低 RTT → 値 **中** |
| 遠距離 | 低 freq × 高 RTT → 値 **低** (どうせ 1 回) | **中 freq × 高 RTT → 値 高** |
| 最適キャッシュ | **近傍寄り** (≒ Part 1 均一結論) | **遠方ノードも積む価値が出る** |

- **パターン A**: 遠方は freq が立たず、高 RTT でも値が出ない → 近傍優先。均一時の結論 (近傍ノード/エッジ捨て) がほぼ維持される。
- **パターン B**: 遠方が freq を稼ぐので、`高 RTT × 中 freq` が近傍を**逆転しうる** → 遠方ノードを保持する動機がここで初めて生まれる。§2.6 の node/edge 配分反転は、実体としてはこのパターン B が引き起こす。

**§2.5 の規律はここでも効く**: `f(d)` は重み、`freq` が実測の予測子。
> **「遠いから入れる」ではない。「遠くて かつ 実際に頻度が立つ から残す」。** パターン B はその「遠方で頻度が立つ」条件を満たしうる、という話に過ぎない。距離単独では依然として何も決めない。

**実験での出し方**: 既存ログから各 (start, entity) の `(d=dist(start,e), freq)` 同時分布を集計し、**分割方式 (種別分割 / Louvain 粒度違い) を振って A↔B を作り分け**、各レジームで `freq×f(d)` 上位がどこに来るか (近傍 vs 遠方) を可視化する。これが「分割方式・軌道パターンで最適キャッシュが変わる」の直接証拠になる。(α は補助つまみとして併せて振ってよい。)

### 2.7.5 漸近 RTT モデル (hop 順で RTT を変える・収束先共通)

§2.4–2.7 は RTT を**グラフ距離** `f(d)` の関数にした(空間軸)。これと別に、RTT を **walk の hop 順** `h`(=hops_done, bipartite hop)の関数にする**時間軸の漸近モデル**がある。「遠くから漸近 / 近くから遠く」を hop 順で直接表すのがこれ。

**定式化** ── 減衰 `g(h)`(`g(0)=1, g(∞)=0`。`g(h)=(1−α)^h` が既存 restart 減衰と一致し追加パラメータ不要 / `exp(−h/τ)` も可)を使い、**収束先 R∞ を共有**して符号だけ変える:
```
上から漸近 (遠→近, 大→小):  RTT↓(h) = R∞ + A·g(h)     h=0:R∞+A → h→∞:R∞
下から漸近 (近→遠, 小→大):  RTT↑(h) = R∞ − A·g(h)     h=0:R∞−A → h→∞:R∞   (A≤R∞)
```
- **R∞**=共有の収束 RTT(「最終的に収束する RTT を同じにしたい」を満たす)、**A**=初期ズレ幅、α/τ=収束速度。A も揃えれば上下は鏡像の過渡だけが違う。

**時間への反映**:
```
全体時間 = base + Σ_{miss at hop h} RTT(h)
上−下の差 = Σ_{miss} 2A·g(h)   ← 小さい h(序盤)の miss に集中
```
- **上から**(序盤が高 RTT)→ **early-hop を保持する policy** が有利。
- **下から**(終盤が高 RTT)→ **深い hop の再訪を守る policy** が有利。
- R∞ 共通なので、上下の差は「どの hop の miss を減らせたか」という**過渡部分だけ**= policy の早い/遅い得意を公平比較できる。

**データ要件 (hop が要る)**:
- **cache=none**: miss=全 lookup → `access_by_distance.csv`(hop 別 access)から即計算可、再生成不要。
- **lru/memo/提案**: hop 別 miss は集計に無い → seed 固定で決定的な **walk_events 上で policy 再現**(各イベントに hop あり)。`policy_compare_summary.csv` は node/edge 別 miss は持つが hop 別ではない。

**空間 (f(d)) vs 時間 (RTT(h)) の使い分け**: f(d)=サーバ配置(分割)由来の構造コスト。RTT(h)=walk が「収束へ向かう過渡」を表す動的コスト。漸近モデルの主役は後者。両者は直交し、`RTT(start,e,h)=f(d)·s(h)` のように積で合成も可能(まず片方ずつ)。

### 2.8 明確にすべき課題リスト (オープンクエスチョン)

1. **【最上流の設計】どの分割を前提にするか** (§2.4): (i) 種別分割 (node/edge 2 台、距離は無関係・RTT 比 `r`) と (ii) 局所性分割 (Louvain many-server、距離=RTT・傾き β)。**両方を比較するのが本命**。RTT 不均一の源泉は α でなく分割方式。
2. **【検証】不均一は本当に配分を変えるか**: §2.6 の反転閾値 ((i) は `r`、(ii) は β) を既存ログ上で**後付け計算**できる (各ヒットに RTT 重みを掛けて重み付き OPT を回すだけ)。← **最初にやるべき安価な実験** (§2.9)。
3. **【目的関数】評価軸の差し替え = 「時間」を出す** (§2.0): `auth_calls`(ヒット率) → **`全体の時間 = 基準時間 + Σ_{miss} RTT`** (秒)。policy 間は `節約時間 = Σ_{hit} RTT_saved` で比較。均一は RTT 定数の特殊ケースとして同居させ ablation で効果を分離。
4. **【手法】GDSF cost 項の組込み**: `V(e)=[max(0,freq−δ)+θ·w_struct]·RTT_saved(e)`。uniform → heterogeneous で滑らかに繋ぐ。
5. **【リスク管理】距離の二役を混同しない** (§2.5): RTT 重みは**重みのみ**。admission・予測に距離を使わない。prior と RTT 重みの二重距離を避ける。
6. **【データ】`f` の形と妥当性**: (ii) では合成 (Louvain コミュニティ間ホップ数 × 単位遅延) で β をスイープし「**β–最適 node/edge(遠方) 配分**」の閾値曲線を主図に。実測トポロジがあれば実測表で置換。
7. **【発展】分割方式そのものを設計変数にできるか**: walk パターンを所与として RTT 総和を最小化する分割 (= 通る経路が境界を跨ぎにくい分割) は何か。キャッシュと分割の co-design は将来課題。

### 2.9 最短の次アクション

> **既存の OPT/LRU 実測ログ (walk_events) と BFS 距離計算 (`access_density_by_distance.py` が既に .gr から各 start の最短距離を出せる) を join するだけ**で、新規サーバ計装なしに検証できる。2 段構え:
>
> **(1) 同時分布の確認 (分割・軌道パターンの効果)** ── まず「頻度 × 距離の同時分布が分割/軌道で動く」を見る:
> 1. 各 (start, entity) に `(d=dist(start,e), freq)` を付与。
> 2. **分割方式 (種別分割 / Louvain 粒度違い) を振って** パターン A↔B を作り分け、`(d, freq)` のヒートマップと `freq×f(d)` 上位の位置 (近傍 vs 遠方) を比較。
> 3. 期待: A では上位が近傍に、B では遠方にも上位が立つ → 「分割/軌道で最適キャッシュが変わる」の直接証拠。
>
> **(2) 配分への影響 (閾値曲線)** ── 各ヒットを `f(d)=1+βd` で重み付けし、**重み付き OPT / LRU / 提案** を β を振って再計算:
> - 出力: 横軸 β、縦軸「最適キャッシュ内の遠方 (or edge) 比率」。
> - **β=0 で Part 1 の結論 (近傍・ノード偏重) を再現し、β を上げると遠方/edge 比率が立ち上がる**なら、不均一化は本物の研究課題。立ち上がらなければ「距離不均一でも配分は不変」という (それはそれで明快な) 結論。
> - パターン B のログほど立ち上がりが早いはず (遠方 freq があるため)。A と B で閾値曲線を 2 本描けば、§2.7 の主張がそのまま図になる。

## まとめ (1 枚)

- **流れ**: 越境認可 RTT を削りたい → 容量無制限は非拡張的 → 容量 100 に有界化 → 47% one-hit が容量を殺す → 本丸は IN(admission) → 構造プライアは無効、頻度保護で OPT≈Memo に迫れる → **エッジが主戦場・node/edge 非対称配分** → ここまで全部「均一 RTT (時間∝認可回数)」。
- **最終地点 (不均一 RTT)**: 目的関数が「ヒット数」→「節約 RTT 総和」に変わる。**距離は予測子としては死んだが、ヒット価値の重みとして復活**。GDSF の眠っていた cost 項が効く。
- **RTT 不均一の源泉 = パーティショニング (§2.4、α ではない)**: **(i) 種別分割** (現状 node/edge 2 台、距離は RTT 無関係 → node/edge の RTT 非対称に縮約) と **(ii) 局所性分割** (Louvain many-server、距離=RTT が成立 → `f(d)`)。**model (c)「距離=RTT」が効くのは (ii) のときだけ。** 同じ walk でも分割を変えれば RTT 列もキャッシュすべきノードも変わる。
- **モデルの核心 (§2.7、(ii) 前提)**: 価値 = `freq × f(d)`。RW の軌道には **A: 近傍から徐々拡散** (遠方は低 freq) と **B: 遠征→帰還** (遠方も中 freq) があり、**頻度×距離の同時分布が分割/軌道で変わる → 最適キャッシュ集合が変わる**。∴ **RTT と頻度を同時に**考える必要がある。
- **課題の核心**: 均一で決着した **近傍/ノード偏重の配分が、(i) では RTT 比 `r`・(ii) では傾き β で反転しうる**。両レジームで閾値曲線を描くのが貢献。既存ログ × BFS 距離の後付け重み付けでまず安価に確かめる。
- **唯一にして最大の落とし穴**: 距離は Part 1 で否定された死んだ予測子。**重みとしてのみ**使う。「遠いから入れる」ではなく「**遠くて かつ 頻度が立つ から残す**」(§2.5)。
